# 🚀 Antigravity Project Context: FarmPilot

This document provides a high-level technical context for AI coding agents working on the **FarmPilot** project.

## 📌 Project Overview & Mission
**FarmPilot** is an intelligent precision-farming ecosystem developed for the UTM HACKathon. Its mission is to bridge the gap between traditional farming and data-driven agriculture by providing farmers with a "Co-Pilot" for their crops.

The system doesn't just monitor data; it **interprets** it based on pre-defined botanical knowledge (Crop Profiles) and suggests actionable tasks via an AI Agent.

---

## 🛠️ Technology Stack
- **Backend**: FastAPI (Python 3.10+)
  - **Database**: SQLite with SQLAlchemy ORM (Type-safe `Mapped` columns)
  - **Server**: Uvicorn with auto-reload.
- **Frontend**: Next.js 15 (React, TypeScript)
  - **State Management**: React Context (`PlantContext.tsx`) for global data synchronization.
  - **Styling**: Tailwind CSS for layout, Framer Motion for premium feel animations.
  - **Icons**: Lucide React.

## 💾 Core Data Models (entities.py)

### 1. Knowledge Base
- **`CropProfileRecord`**: The "Template" for a plant species. Stores botanical names and lifespan.
- **`GrowthStageRecord`**: Granular rules for a specific profile (e.g., "Seedling" for Chili).
  - **Metrics**: `temperature`, `humidity`, `soil_moisture`, `ph`, `dli`.
  - **Columns**: Stores `min`, `max`, and `optimal` values for each metric.
  - **Notes**: `ai_cultivation_notes` (JSON) and `irrigation_cycle`.

### 2. Live Monitoring
- **`ActivePlantRecord`**: The real-time state of a physical plant.
  - Tracks `health_score`, `day_count`, and current sensor readings (`temperature`, `ph`, etc.).
- **`SensorRecord`**: Digital twins of hardware sensors.
  - Tracks `battery_level`, `status`, and the `current_value` being pushed to the plant.

### 3. Action & Intelligence
- **`AgentTaskRecord`**: Tasks generated by the system (e.g., "Increase Water").
  - Includes `reasoning`, `confidence_score`, and `predicted_impact`.
- **`NotificationRecord`**: User alerts based on agent tasks or sensor threshold breaches.

## 🔌 Primary API Endpoints
- `GET /api/profiles`: Returns the full knowledge base (Profiles + Stages).
- `GET /api/plants`: Returns all active plants with their current status.
- `POST /api/plants`: Creates a new plant instance based on a `cropProfileId`.

## 💡 Implementation Insights for Agents

### 1. Data Fetching Strategy
The frontend uses a **Single Source of Truth** pattern via `PlantContext.tsx`. 
- **Do not** perform separate `fetch` calls in individual components unless it's for a one-off action (like a specific task update).
- **Always** use the `usePlant()` hook to get the `activePlant` or `activeProfile`.

### 2. The "Knowledge-Check" Logic
The system evaluates plant health by comparing the `ActivePlantRecord` metrics against the current `GrowthStageRecord` optimal ranges. If a metric is out of range, the Agent logic (in development) should trigger an `AgentTaskRecord`.

### 3. Hackathon Shortcuts
- **Migrations**: We use `_ensure_growth_stage_columns()` in `main.py` for lightweight schema updates without Alembic.
- **Mock Data**: `seed.py` is the source of truth for the "Knowledge Base". Update this to add more crop types.

### 4. UI/UX Standard
- Use `framer-motion` for all state transitions (e.g., switching plants).
- Maintain a **Dark/Premium** aesthetic as established in `globals.css`.
